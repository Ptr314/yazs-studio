# Встраиваемый плеер для игр: варианты и замеры

Разработчики игр для Агата с ЯЗС просят плеер, который можно встроить в игру. Главное требование -
минимум памяти. Здесь разобраны варианты, для каждого собран прототип: компилятор `.YZ` в текст
для AS65 и плеер на 6502. Все прототипы измерены на 11 мелодиях Alice in Wonderland. План опыта -
`PLAN.md`.

## Условия

- **Вызов.** У каждой мелодии и каждого звукового эффекта свой вход: `JSR tune_N`, звук играет до
  конца, потом RTS. Эффекты тоже блокирующие: это решение пользователя, один плеер на все.
- **Точность.** Записи в регистры ячейки - те же, что у ЯЗС-Студии, тик в тик. Это модель
  `studio/pyplay.py` плюс хвост плеера Студии: 100 тиков ноты отпускаются, потом тишина.
  Упрощения с потерями посчитаны отдельно.
- **Сборка.** Компилятор берет все мелодии игры сразу, поэтому словари, инструменты и повторы
  общие на всю игру. Адреса в данных абсолютные, их ставит ассемблер игры.

## Общая часть всех вариантов

`players/common.a65` (77 байт):
- **Вход - 3 байта на мелодию:** `tune_N: jsr yzplay`, данные лежат сразу за JSR. `yzplay`
  снимает адрес возврата со стека как указатель данных. Его RTS в конце возвращает к тому, кто
  позвал `tune_N`.
- **Ячейка:**
  - PHP/SEI;
  - `+F = $C0`, тишина, режим 3 всем шести счетчикам;
  - таймер N, пуск, сброс флага;
  - тик - опрос D7 `+0`, сброс флага записью `$80` в `+7`;
  - выход: `+F = $C0`, тишина, сброс флага, PLP, RTS.

  Это `card_init`, `set_timer`, `wait_tick` и `card_off` из `player/player.a65`.
- **Слот** - константа сборки `YZ_CARD` (`$C090` - слот 1).
- **Нулевая страница** (`YZ_ZP`) и ОЗУ переменных (`YZ_RAM`) задаются в игре. Пока звук играет,
  игра стоит, поэтому плееру можно отдать любые временные ячейки: после выхода они не нужны.

## Варианты

| | Что лежит в игре | Плеер |
|---|---|---|
| **A** «как SID» | `.YZ` v1 без строк и имен: кадры по 8 каналов, паттерны, инструменты с макросами по тикам | движок Студии `engine.a65` без интерфейса: все эффекты, ударные, таблицы периодов и вибрато (`trk_full.a65`) |
| **C** трекер под набор | кадры только занятых каналов, паттерны с номерами нот из словаря игры, инструменты RLE | движок только с тем, что есть в мелодиях; здесь - без эффектов (`trk_min.a65`) |
| **B1** поток регистров | все записи модели по тикам: «регистр, значение», конец тика с числом пустых | ~60 байт сверх общей части (`reg.a65`) |
| **B2** поток со словарями | то же, но байт `01 ccc vvv` - регистр канала из словаря 8 значений, `10 ccc` + индекс - период из словаря | `reg.a65`, B_DENSE |
| **E** поток с повторами | B2 плюс ссылка «сыграть n байт с адреса» на уже лежащий в памяти кусок любой мелодии (LZ без буфера) | `reg.a65`, B_REF |
| **D** нотный поток (свой) | поток каждого занятого канала без кадров: байт `ddd nnnnn` - нота из словаря и длительность из таблицы 7 значений, инструмент, вызов фразы; огибающие инструментов RLE | `note.a65` + `tone.a65` |
| **F** музыка как код | `LDA #/STA` на каждую запись, `JSR` на тик | только расчет |

C и D работают на одной части тонового канала (`tone.a65`):
- удар через тик после разбора, с D4 = 0 на этот тик, как у движка;
- огибающая регистра и отпускания - RLE-пары (тиков, значение);
- период - из словаря игры;
- запись только при изменении.

Компилятор C и D проверяет, что высота меняется только при ударе, а регистр - только по
макросам. Мелодию, где это не так, он отвергает с объяснением.

## Мелодии Alice

`studio/sid2yz.py docs-external/sid-examples/Alice_In_Wonderland.sid --all --out out/embed/alice`
дает 11 джинглов по 7-25 с, всего 5292 байта `.YZ`:
- **Каналы:** заняты только тоновые 1-2.
- **Команды:** ноты, по одному `@инструмент` и `DETUNE -4` на канал; эффектов нет.
- **Инструменты:** два, одинаковые во всех 11 файлах. Макрос регистра развернут по тикам (25 x
  HIT, ~74 x HOLD, затем полосы), поэтому каждый занимает 113 байт, а в RLE - 13.
- **Ноты:** 651 нота, 28 разных высот, 11 разных длительностей; 9 строк - у половины нот.
- **Повторы:** мелодии 01, 05 и 11 - варианты одной темы.

## Выводы

1. **Для игры с несколькими мелодиями лучший вариант - D.**
   - Все 11 джинглов вместе с плеером - 1231 байт: в 4.3 раза меньше самих `.YZ` и в 6.5 раза
     меньше универсального движка A.
   - Музыка - около 1 байта на ноту: 645 байт потоков и фраз на 651 ноту.
   - Плеер - 489 байт, словари и инструменты - 97.
2. **Универсальный движок (A) для игр не годится.** 2 КБ кода и 1.6 КБ таблиц (вибрато 1 КБ,
   периоды 384, div/mod 192) нужны еще до первой ноты. Данные - те же `.YZ` без 76 байт строк.
3. **Поток регистров (B) прост, но раздувает данные.** Огибающая каждой ноты разворачивается в 3-4
   записи, и B2 выходит почти таким же, как `.YZ`. Повторы (E) дают -27%, но данные D все равно в
   4 раза компактнее (645 байт против 2576). Зато код самый маленький, поэтому поток выигрывает,
   пока музыки в игре меньше ~15-20 с:
   - одна мелодия до 16 с - B2 или E на 20-160 байт меньше D (у 25-секундной 01 D меньше на 264);
   - две самые короткие (06 и 08, ~14 с) - B2 514 байт, D 575;
   - три короткие (06, 08, 10, ~21 с) - D 623, E 659, B2 671; дальше разрыв только растет.
4. **Незанятые каналы ничего не стоят в B, C и D:** нет ни данных, ни прохода плеера по ним. У A
   каждый кадр несет 8 номеров паттернов (у Alice заняты 2) и каждый тик обходит 8 каналов.
5. **Трекер под набор (C) почти вдвое больше D.**
   - Кадры держат каналы вместе. Повтор возможен только целым паттерном, а у Alice паттерны не
     повторяются.
   - D повторяет любые куски любой длины, в том числе между мелодиями.
   - C разумен, если мелодии используют эффекты по тикам (вибрато, арпеджио, скольжения): они
     дешевле в движке, чем в данных.
6. **Упрощения с потерями здесь почти ничего не дают:**
   - без хвоста отпускания: -44 байта кода у C и D, -4..-22 байта данных у B;
   - округлять нечего: длительности у Alice уже на сетке;
   - инструменты различаются полосами, сливать их - менять тембр.

   Точность обходится без потерь в объеме.
7. **Готовый распаковщик LZ.** Если он уже есть в игре и на время мелодии свободен буфер под ее
   распакованный поток, сжатый поток B2 займет ~660 байт. Это оценка deflate, нижняя граница; у
   распаковщиков для 6502 на 10-25% больше. С плеером выходит ~930-1090 байт, сравнимо с D (1231).
   Нужен буфер до 900 байт (мелодия 01), растет он с длиной мелодии. D сжимается хуже (645 -> 532),
   его повторы уже вынесены.
8. **Время.** До 839 тактов на тик у D, до 3259 у A. При тике 100 Гц у процессора около 10 000
   тактов, запас большой. Опрос флага не теряет тиков.

## Что D пока не умеет

Все это есть в `.YZ`, но не в мелодиях Alice. Такие мелодии компилятор D сейчас отвергает:
- эффекты высоты (вибрато, арпеджио, скольжения, PORTA, макросы высоты);
- эффекты регистра (BUS, TREMOLO, RETRIG, CUT, DELAY);
- лиги, ударные, TEMPO;
- повтор с кадра `loop`. Блокирующий вызов должен вернуться; заставке с бесконечной музыкой нужен
  выход по клавише.

Пути расширения:
- **Сырые записи:** запись, которую модель «нота + огибающая» не объясняет, идет командой
  потока. Так пройдут редкие скольжения и эффекты SID-переводов.
- **Модули движка условной сборкой, только когда мелодии их используют.** Цена по листингу A:

  | Модуль | Код, байт | Таблицы, байт |
  |---|---|---|
  | вибрато | ~70 | 64 на каждую используемую глубину |
  | арпеджио | ~70 | |
  | PORTA | ~110 | |
  | скольжение и макрос высоты | ~30 + 100 (границы) + 43 (шаг макроса) | |
  | расчет периода по полутонам вместо словаря | ~150 | 592 |
  | ударные | ~40 | |

- **Звуковые эффекты.** Это та же мелодия в одну-две ноты. Удар и щипок звучат на огибающих
  самой платы, поэтому эффект в D стоит несколько байт.

## Проверка

- **На 6502** (`run6502.py`): эмулятор 6502 конвертера SID, ячейка в слоте 1. Каждый вариант
  проигрывает каждую мелодию в трех сборках: игра из всех 11, игра из одной, игра из первых k. Это
  88 прогонов на вариант. Записи в счетчики, таймер и каналы сверяются с моделью по тикам
  (множества записей тика). Отдельно сверяются вход и выход: режимы счетчиков, таймер, `+F`,
  тишина. Итог: **все варианты, все прогоны - совпали**.
- **В eCat3** (`ecat3.py`, консольная сборка через `studio/render.py`):
  - игра из 11 мелодий - на диске 840 КБ, ее запускает «Быстропускалка»;
  - снимки `yazs.irqs`/`regs`/`counters` каждые 100 мс, поканальная сверка с моделью, как в
    `verify.py`.

  | | A | C | B1 | B2 | E | D |
  |---|---|---|---|---|---|---|
  | снимков совпало | 1411 | 1415 | 1418 | 1418 | 1417 | 1419 |
  | внутри тика | 10 | 6 | 4 | 4 | 5 | 2 |
  | между мелодиями (тишина) | 127 | 130 | 127 | 129 | 129 | 130 |
  | расходятся | 0 | 0 | 0 | 0 | 0 | 0 |

  - Тиков по флагу таймера у всех - 14184, ровно как у модели.
  - «Внутри тика» - снимок попал между записями одного тика. Бывает и так, что новый период в
    режиме 3 еще не вступил: `yazs.counters` показывает период в действии.
  - WAV всей игры: `out/embed/ecat3_D/game_D.wav`, `out/embed/ecat3_A/game_A.wav`.

## Дальше

Выбран D. Инструмент сделан: `studio/yz2asm.py`, шаблон `player/yzplay.a65`, `docs/yz2asm.md`.
Здешние прототипы остались как замер и в инструмент не входят. Решения:
- **синтаксис:** выдача - общее подмножество AS65 без `if` и `lo()/hi()`; флаги разрешает сам
  `yz2asm`;
- **выход по клавише:** ключ `--key`, 5 байт;
- **слот:** ключ `--slot`, константа сборки;
- **сырые записи:** сделаны для периода (`$F7`), поэтому проходят скольжения, вибрато и арпеджио.
  Регистр - пока нет.
